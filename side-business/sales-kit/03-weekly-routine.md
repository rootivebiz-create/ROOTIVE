# 03 毎週のやること と AI への頼み方

社長が使える時間は **週 1〜2 時間** です。
下書き・調べもの・記録は AI（Claude Code）がやり、社長は「読む」「OK／やめる」「商談で話す」だけにします。

---

## 1. 1 週間の時間の使い方

| いつ | 時間 | やること | 資料 |
|---|---|---|---|
| 月曜の朝 | 10分 | AI の週報を読み、今週送るものに「OK／やめる」を返す | この資料 |
| 予約が入った日 | 30分 × 1〜2件 | 商談（オンラインか電話） | 07 |
| いつでも | 10分 | 同業の知り合い 1〜2 人に、紹介のお願いを LINE で送る | 04 |
| いつでも | 10分 | AI が作った見積書・提案書・レポートを読んで、送るか決める | 07 |
| 導入中のお客様がいる週だけ | 30分 | 最初の打ち合わせか、検収の立ち会い | ― |
| 月初に 1 回 | 15分 | 先月の数字を見る。FAX の見出しを決める | 06・13 |
| **合計** | **60〜120分** | 2 時間を超えそうなら、新しい商談は翌週へ回す | |

**その日のうちにやること（1 分）**：停止の申し出が来たら、すぐ止める（下の「停止」の頼み方）。

---

## 2. 最初に AI に貼る「前置き」

Claude Code を開いたら、最初にこれを貼ります（毎回、会話の始めに 1 回）。
Claude Code は **しめ日ラボのフォルダ**（個人のリポジトリに移したもの → 01 の D）で開きます。会社のリポジトリの中では開きません（会社の設定も読み込まれるため）。

```text
これから、しめ日ラボ（私の個人事業）の営業の手伝いをお願いします。次を必ず守ってください。
- sales-kit/README.md の「守ること」に従う。
- メール・LINE・FAX の送信、申し込み、支払いの前に、必ず私に「OK」を聞く。
- 会社（私が代表をしている会社）の名前・画面・データ・コード・お客様の名前を使わない。
  除外リストにある会社には何も送らない。
- ドライバーの名前・口座・免許などの本番の個人情報は扱わない。ファイルに入っていたら、作業を止めて知らせる。
- 料金は site.config.ts の PLANS だけを見る。
- 税金・法律の話には「最終的な判断は税理士・弁護士・社労士に」と書き添える。
- 補助金が使える、導入◯社、測っていない時短の数字、ミスゼロ、必ず合う、協会の推薦、とは書かない。
- 答えは短く。私はスマホで読みます。
```

> Gmail・Google カレンダー・Google ドライブを Claude につないでいれば、AI がメールや予定、営業記録のスプレッドシートを直接読みます。
> つないでいなければ、必要なメールや表を下の頼み方の【】に貼ってください。

## 3. 毎週の頼み方（そのまま貼る）

### 3-1. 月曜：週報

```text
今週の反響をまとめて。
- 先週月曜から今日までに来た問い合わせ（相談フォーム・メールの返信・LINE・電話のメモ・FAX の返信）。相談フォームのものは、通知の「流入元」の 1 行から、どこから来たか（FAX ならどの見出しか）も書く（→ 13）
- 予約済みの商談（日時・会社・予約フォームに書かれたこと）
- 進んでいる案件（お試し・見積・契約）と、次にやること
- 停止の申し出と、止めたかどうか
- 今週送る予定のもの（紹介のお願い・メール・FAX）の件数と、OK が要るもの
- 今週の私の時間の見込み（2 時間を超えそうなら、どの商談を翌週に回すかの案）
最後に「OK が要るもの」を番号付きで並べて。私は「1 OK、2 やめる」の形で返します。
【Gmail などをつないでいないときは、ここに問い合わせのメールや記録を貼る】
```

### 3-2. 停止の申し出（その日のうちに）

```text
停止：【会社名】【メールアドレス か FAX 番号】【どこから来たか：メール返信／FAX／電話／フォーム】
停止リストに入れて、今後の送付リスト（メール・FAX）から外したことを確かめて。
相手に返す短いお詫びの文も作って（FAX や電話で来たときは不要）。
```

### 3-3. 商談の前

```text
【日時】に【会社名】（【ホームページの URL】）と商談です。
sales-kit/07-meeting-and-hearing-sheet.md に沿って、次を 1 枚にまとめて。
- 会社の要約（公開されている情報だけ。事業・地域・案件の種類・ドライバー募集の有無）
- 除外リストに入っていないかの確認
- 予約フォームに書かれていたこと
- 今回とくに聞きたい質問 5 つ（ヒアリングシートから選ぶ）
- 見せるデモの場面 2 つ
```

### 3-4. 商談のあと

```text
【会社名】との商談が終わりました。メモを貼ります。
【商談のメモ・聞いたこと（箇条書きでよい）】
次を作って。
1. 今日送るお礼のメール（07 のひな形で）
2. ヒアリングシートを埋めたもの
3. 見込みの判断（07 の基準で「進める／様子見／止める」と理由）
4. 次にやることと期限
5. 営業記録（商談のシート）に入れる 1 行
```

### 3-5. 提案書

```text
【会社名】向けに提案書を作って。
- 商談のメモ：【貼る、または「3-4 で作ったもの」】
- /kit/proposal?company=【会社名】 の URL を作り、中身が商談で聞いた困りごとに合っているか確かめる
- 合わないところがあれば、どこを直すべきか教えて（料金は PLANS から変えない）
- 送るときのメール文（3 行程度）
```

### 3-6. 見積書

```text
【会社名】の見積書を作って。
sales-kit/08-estimate-template.md のひな形で。
- プラン：【お試し／支払明細パック／利益まるごとパック】、オプション：【運行記録 あり／なし】
- 金額は site.config.ts の PLANS・OPTIONS から。税抜・消費税・税込を分けて書く
- 屋号・氏名・住所・登録番号・有効期限（発行から30日）
- 支払条件は 08 のとおり（初期費用の期日が納品日から 60 日を超えないこと。月額は毎月末締め・翌月末払い）
- 保守に含むものは MAINTENANCE_INCLUDES のとおり
- サーバー代はお客様が直接払うこと（金額は断定しない）
PDF にできる形で。送る前に私が読みます。
```

### 3-7. 無料診断のレポート

**預かったファイルの置き場所（無料診断・お試しで共通）**
- 預かったファイルは `side-business/private/` に置く（Git には入らない。`.gitignore` で外してある。個人のリポジトリに移したあとは、その直下の `private/`）。デスクトップやダウンロードのフォルダに置いたままにしない
- 終わったら **30 日以内に消す**（無料診断・お試しの報告書を渡した日から数える）。消した日をカレンダーに入れ、消したらお客様にメールで知らせる
- 本番の個人情報（ドライバーの名前・口座・住所）は **入れてもらわない**。名前は番号に置きかえてもらう

AI に渡す前に、社長がファイルを 1 回開き、ドライバーの名前・口座・住所が入っていないかを目で見ます（1 分）。
入っていたら AI には渡さず、10 の「名前や口座が入っていたとき」の返信文を送ります。

```text
先月分の無料診断レポートを作って。sales-kit/10-diagnosis-report-template.md のひな形で。
- 受け取ったファイル：side-business/private/【ファイル名】
- 最初に、列の名前（1 行目）だけを見て、名前・口座・住所・免許の列が無いか確かめて。
  あれば中身は読まずに作業を止めて、10 の「名前や口座が入っていたとき」の返信文だけを作って。
- 無ければ、次の 4 つを 1 枚にまとめて：
  1. 明細の中の計算の検算（lib/payroll を使う。合わなかった行と、考えられる理由）
  2. 仕入明細書として足りない記載
  3. 支払期日が役務の提供から 60 日を超えていないか
  4. 免税のドライバーへの支払で、会社が控除できない消費税の額（80% と 70% の期間を分ける）
- 「計算の結果です。税務・法律の判断ではありません。最終的な判断は税理士・弁護士に」と書く。
- 送るときのメール文と、次の一歩（お試しか 30 分の相談）の案内も作って。
```

### 3-8. お試しの報告書

無料診断と同じく、AI に渡す前に社長が名前・口座・住所が入っていないかを目で見ます。
ファイルの置き場所と消す期限も、3-7 の「預かったファイルの置き場所」と同じです（`side-business/private/` に置き、30 日以内に消す）。

```text
【会社名】のお試しの報告書を作って。sales-kit/10-diagnosis-report-template.md の形で。
- 受け取ったファイル：side-business/private/【ファイル名】、お客様の実際の支払合計：【金額】
- 最初に、列の名前（1 行目）だけを見て、名前・口座・住所・免許の列が無いか確かめて。あれば作業を止めて知らせて。
- 合った行・合わなかった行と、その理由（ルールの違いか、手入力のミスか）を 1 枚に
- 30 分の説明で見せる順番
- 本契約に進むときの見積（お試しの費用を初期費用から差し引く）
```

### 3-9. 紹介のお願い

```text
今週の紹介のお願いを作って。
相手：【名前】、関係：【親しい友人／知り合い／商談した人】、最後に話したのは：【いつ・何の話】
sales-kit/04-referral-messages.md の文面から選んで、相手に合わせて直して。
除外リストに入っていないかも確かめて。
```

### 3-10. メールでの案内

```text
今週のメールの送り先を【50】社選んで、1 社ずつ文面を作って。
sales-kit/05-outbound-email.md の手順とルールで。
- きっかけ：【70% ／ フリーランス法 ／ 安全管理者 ／ おまかせ】
- 地域：【関東／全国など】
出すもの：送付記録に入れる表（会社名・見つけた URL・アドレス・お断り表示の確認・きっかけ）と、各社の件名と本文。
私が OK を出すまで送らない。OK のあと、1 日 20〜30 通に分けて送る（または Gmail の下書きにする）。
```

### 3-11. FAX（月 1 回）

```text
来月の FAX の準備をして。
sales-kit/06-fax-dm-guide.md と 13-funnel-and-kpi.md の数字を見て、
- 今月の結果のまとめ（見出しごとの送信数・反響・停止）
- 来月の見出しの案を 2 つ（理由つき）と、送る件数・費用の見込み
- /kit/fax の URL と、PDF にする手順
- リストから停止リストと除外リストを外したかの確認
```

### 3-12. 月初：先月の数字

```text
先月の数字をまとめて、sales-kit/13-funnel-and-kpi.md の表に入れて。
判断のルールに当てはまるものがあれば、何を変えるかの案を 3 つまで。
3 か月目・6 か月目の見直しの月なら、そのルールで判断して。
```

### 3-13. 契約書

```text
【会社名】の契約書一式を、sales-kit/09-contracts.md の弁護士に見てもらった版から作って。
（弁護士の確認がまだなら、作らずにそう知らせて。）
プラン：【】、開始日：【】、特記事項：【】。
変えたところに印を付けて。ひな形から外れる内容があれば、弁護士に聞くべきか教えて。
```

---

## 4. 月に 1 回・節目にやること

- **月初**：先月の数字（3-12）と FAX の見出し（3-11）
- **月末の締めのとき**（会社の承認を得ている場合だけ）：自社の月末の締め作業にかかった時間を記録する。あとで「例」として使える実測の数字になる。使う前に会社に確認する（→ 02 の別紙 7）
- **3 か月ごと**：会社への報告（→ 02）。AI に「会社への報告を 02 の形で作って」と頼む
- **3 か月目・6 か月目**：続けるか変えるかを決める（→ 13）

---

## 5. やらないこと

- 商談を 1 週間に 3 件以上入れない（予約の枠は週 2 枠）
- AI の下書きを読まずに送らない
- 停止の申し出を翌日に回さない
- 会社のパソコン・スマホ・メール・勤務時間を使わない
- 無料の相談で、税金・法律の判断を言わない（「税理士・弁護士に」と伝える）
