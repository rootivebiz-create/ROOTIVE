# 03 毎週のやること と AI への頼み方

社長が使える時間は **週 1〜2 時間** です。
下書き・調べもの・記録は AI（Claude Code）がやり、社長は「読む」「OK／やめる」「商談で話す」だけにします。

---

## 1. 1 週間の時間の使い方

| いつ | 時間 | やること | 資料 |
|---|---|---|---|
| 月曜の朝 | 10分 | AI の週報を読み、今週送るものに「OK／やめる」を返す | この資料 |
| 予約が入った日 | 30分 × 1〜2件 | 商談（オンラインか電話） | 07 |
| いつでも | 10分 | 同業の知り合い 1〜2 人に、紹介のお願いを LINE で送る | 04 |
| いつでも | 10分 | AI が作った見積書・提案書・レポートを読んで、送るか決める | 07 |
| **お試しがある週だけ** | **45〜60分** | **お試しの納品物を製品で作る**（手元の製品に先月分を入れ、並行運用レポートと突合レポートを出す。下の 3-8） | 10 |
| 導入中のお客様がいる週だけ | 30分 | 立ち上げの打ち合わせか、検収の立ち会い | 製品の README |
| 月初に 1 回 | 15分 | 先月の数字を見る。FAX の見出しを決める | 06・13 |
| **合計** | **60〜120分** | お試しがある週は商談を 1 件まで。2 時間を超えそうなら、新しい商談は翌週へ回す | |

**その日のうちにやること（1 分）**：停止の申し出が来たら、すぐ止める（下の「停止」の頼み方）。

---

## 2. 最初に AI に貼る「前置き」

Claude Code を開いたら、最初にこれを貼ります（毎回、会話の始めに 1 回）。
Claude Code は **しめ日ラボのフォルダ**（個人のリポジトリに移したもの → 01 の D）で開きます。会社のリポジトリの中では開きません（会社の設定も読み込まれるため）。

```text
これから、しめ日ラボ（私の個人事業）の営業の手伝いをお願いします。次を必ず守ってください。
- sales-kit/README.md の「守ること」に従う。
- メール・LINE・FAX の送信、申し込み、支払いの前に、必ず私に「OK」を聞く。
- 会社（私が代表をしている会社）の名前・画面・データ・コード・お客様の名前を使わない。
  除外リストにある会社には何も送らない。
- ドライバーの名前・口座・免許などの本番の個人情報は扱わない。ファイルに入っていたら、作業を止めて知らせる。
- 料金は site.config.ts の PLANS だけを見る。
- 税金・法律の話には「最終的な判断は税理士・弁護士・社労士に」と書き添える。
- sales-kit/README.md の「言わないこと」を書かない（補助金・導入◯社・測っていない時短の数字・完全自動・ミスゼロ・必ず合う・
  適法／違反・仕入税額控除できます・未払いを取り戻せます・報酬を下げる話・ほかの製品の名前と比べ・「ほかには無い」・協会の推薦）。
- 元請との差は「少ない可能性がある差」、見張り番は「記録から分かる事実と根拠」と書く。
- 製品のデモの URL は {製品のデモの URL}（NEXT_PUBLIC_PRODUCT_DEMO_URL ＋ /demo/start）。未設定なら、その行を消す。
- 答えは短く。私はスマホで読みます。
```

> Gmail・Google カレンダー・Google ドライブを Claude につないでいれば、AI がメールや予定、営業記録のスプレッドシートを直接読みます。
> つないでいなければ、必要なメールや表を下の頼み方の【】に貼ってください。

## 3. 毎週の頼み方（そのまま貼る）

### 3-1. 月曜：週報

```text
今週の反響をまとめて。
- 先週月曜から今日までに来た問い合わせ（相談フォーム・メールの返信・LINE・電話のメモ・FAX の返信）。相談フォームのものは、通知の「流入元」の 1 行から、どこから来たか（FAX ならどの見出しか）も書く（→ 13）
- 予約済みの商談（日時・会社・予約フォームに書かれたこと）
- 進んでいる案件（お試し・見積・契約）と、次にやること
- 停止の申し出と、止めたかどうか
- 今週送る予定のもの（紹介のお願い・メール・FAX）の件数と、OK が要るもの
- 今週の私の時間の見込み（2 時間を超えそうなら、どの商談を翌週に回すかの案）
最後に「OK が要るもの」を番号付きで並べて。私は「1 OK、2 やめる」の形で返します。
【Gmail などをつないでいないときは、ここに問い合わせのメールや記録を貼る】
```

### 3-2. 停止の申し出（その日のうちに）

```text
停止：【会社名】【メールアドレス か FAX 番号】【どこから来たか：メール返信／FAX／電話／フォーム】
停止リストに入れて、今後の送付リスト（メール・FAX）から外したことを確かめて。
相手に返す短いお詫びの文も作って（FAX や電話で来たときは不要）。
```

### 3-3. 商談の前

```text
【日時】に【会社名】（【ホームページの URL】）と商談です。
sales-kit/07-meeting-and-hearing-sheet.md に沿って、次を 1 枚にまとめて。
- 会社の要約（公開されている情報だけ。事業・地域・案件の種類・ドライバー募集の有無）
- 除外リストに入っていないかの確認
- 予約フォームに書かれていたこと
- 今回とくに聞きたい質問 5 つ（ヒアリングシートから選ぶ）
- 5 分の製品のデモで、とくに時間をかける場面（07 の台本から。元請が多い会社なら突合、控除が多い会社なら見張り番）
- 予想される反論と、07 の 6 の答え
```

商談の **5 分前** に、パソコンで {製品のデモの URL} を開いておきます（開くたびに新しい架空の会社ができ、24 時間で消えます）。デモの流れは 07 の「5 分の製品のデモ」。

### 3-4. 商談のあと

```text
【会社名】との商談が終わりました。メモを貼ります。
【商談のメモ・聞いたこと（箇条書きでよい）】
次を作って。
1. 今日送るお礼のメール（07 のひな形で）
2. ヒアリングシートを埋めたもの
3. 見込みの判断（07 の基準で「進める／様子見／止める」と理由）
4. 次にやることと期限
5. 営業記録（商談のシート）に入れる 1 行
```

### 3-5. 提案書

```text
【会社名】向けに提案書を作って。
- 商談のメモ：【貼る、または「3-4 で作ったもの」】
- /kit/proposal?company=【会社名】 の URL を作り、中身が商談で聞いた困りごとに合っているか確かめる
- 合わないところがあれば、どこを直すべきか教えて（料金は PLANS から変えない）
- 送るときのメール文（3 行程度）
```

### 3-6. 見積書

```text
【会社名】の見積書を作って。
sales-kit/08-estimate-template.md のひな形で。
- プラン：【お試し／支払明細パック／利益まるごとパック】、オプション：【運行記録 あり／なし】
- 金額は site.config.ts の PLANS・OPTIONS から。税抜・消費税・税込を分けて書く
- 屋号・氏名・住所・登録番号・有効期限（発行から30日）
- 支払条件は 08 のとおり（初期費用の期日が納品日から 60 日を超えないこと。月額は毎月末締め・翌月末払い）
- 保守に含むものは MAINTENANCE_INCLUDES のとおり
- サーバー代（Vercel の Pro と Postgres。お客様名義で契約）はお客様が各社へ直接払うこと（金額は断定しない。「目安・◯年◯月時点」）
- 立ち上げに入るもの・データはお客様のもの・やめるときは全データを書き出すことは 08 の「前提」のとおり
PDF にできる形で。送る前に私が読みます。
```

### 3-7. 無料診断のレポート（明細だけを見る軽い版）

無料診断は、お試しより手前の軽い入口です（支払明細を見て、検算・記載・期日・負担を 1 枚に）。元請との突合と並行運用は、お試し（3-8）でだけ行います。

**預かったファイルの置き場所（無料診断・お試しで共通）**
- 預かったファイルは `side-business/private/` に置く（Git には入らない。`.gitignore` で外してある。個人のリポジトリに移したあとは、その直下の `private/`）。デスクトップやダウンロードのフォルダに置いたままにしない
- 終わったら **30 日以内に消す**（無料診断・お試しの報告書を渡した日から数える）。消した日をカレンダーに入れ、消したらお客様にメールで知らせる
- 本番の個人情報（ドライバーの名前・口座・住所）は **入れてもらわない**。名前は番号に置きかえてもらう

AI に渡す前に、社長がファイルを 1 回開き、ドライバーの名前・口座・住所が入っていないかを目で見ます（1 分）。
入っていたら AI には渡さず、10 の「名前や口座が入っていたとき」の返信文を送ります。

```text
先月分の無料診断レポートを作って。sales-kit/10-diagnosis-report-template.md の「無料診断のレポート」のひな形で。
- 受け取ったファイル：side-business/private/【ファイル名】
- 最初に、列の名前（1 行目）だけを見て、名前・口座・住所・免許の列が無いか確かめて。
  あれば中身は読まずに作業を止めて、10 の「名前や口座が入っていたとき」の返信文だけを作って。
- 無ければ、次の 4 つを 1 枚にまとめて：
  1. 明細の中の計算の検算（lib/payroll を使う。合わなかった行と、考えられる理由）
  2. 仕入明細書として足りない記載
  3. 支払期日が役務の提供から 60 日を超えていないか
  4. 免税のドライバーへの支払で、会社が控除できない消費税の額（80% と 70% の期間を分ける）
- 「計算の結果です。税務・法律の判断ではありません。最終的な判断は税理士・弁護士に」と書く。
- 送るときのメール文と、次の一歩（お試しか 30 分の相談）の案内も作って。
```

### 3-8. お試しの納品物を製品で作る（お試しがある週・45〜60分）

お試しの納品物は、**本番と同じ製品** で作ります。手で計算しません。AI にも計算させません（数字は製品の画面と PDF から写すだけ）。
使うのは **自分のパソコンで動かす製品**（お客様ごとに別のデータの置き場所）です。
製品のデモ（{製品のデモの URL}）は、架空の会社のデータが最初から入っていて、お客様のデータと混ざるので、**お試しの報告には使いません**（商談で見せるだけ）。

#### 受け取るもの（09 の F「お試しの申込書」と同じ）

1. 先月の稼働の Excel（今の形のまま。**ドライバーの名前は番号に**置きかえたもの）
2. 今の Excel で出した先月の振込額（番号と振込額の 2 列。今の Excel の「振込額」「差引支給」の列そのままでもよい）
3. 元請の支払通知（元請ごとに CSV か Excel。PDF しか無ければ、元請の画面に CSV のダウンロードが無いか見てもらう。無ければその元請は突合から外す）
4. 控除のルールのメモ（ロイヤリティ・管理費・リースなど。いつ・どの書面で合意したかが分かれば）
5. 締め日・支払日・振込手数料をどちらが負担しているか・会社の消費税の計算方法（原則課税・簡易課税・2割特例）
6. ドライバーごとのインボイスの登録の有無（`T＊＊＊＊…` の形で）

**受け取らないもの**：名前・口座・住所・免許・マイナンバー、隠していない登録番号。入っていたら作業を止め、10 の「名前や口座が入っていたとき」の返信文を送ります。

#### 最初に 1 回だけ（手元のパソコンで製品を動かせるようにする）

```bash
cd side-business && npm install
cd product && npm install
```

#### お客様ごと（番号は `C001` のように。会社名はフォルダ名にもファイル名にも使わない）

1. **置き場所**：`side-business/private/C001/` を作り、受け取ったファイルを入れる（`private/` は Git に入らない）
2. **その会社専用のデータで製品を立ち上げる**
   ```bash
   cd side-business/product
   PGLITE_DIR="$(pwd)/../private/C001/db" npm run dev
   ```
   ブラウザで `http://localhost:3300/setup` を開き、会社を作る（会社名は「お試し C001」、利用者は自分）。データは `private/C001/db` に残るので、途中で止めても（Ctrl + C）同じコマンドで続きから。
3. **最初の設定**（ホームの帯「最初の設定」から、上から順に）
   1. 会社の基本：締め日・支払日・振込手数料・消費税の計算方法（登録番号は空でよい）
   2. ドライバー：番号の一覧を貼り付ける（インボイスの登録の有無も）
   3. 元請と案件：元請の名前・案件・単位・受注単価・支払単価（元請の名前は、支払通知のファイルと同じにしておく）
   4. 控除のルール：メモのとおり。合意の日と書面は、分かるものだけ
   5. 先月の Excel を取り込む：取り込み（`/import?m=YYYY-MM`）にファイルを置く → 列の対応 → 名前の確認 → プレビューで **「ファイルの合計と一致」** を見る → 反映する
   6. Excel と比べる（`/parallel?m=YYYY-MM`）：「Excel から貼り付ける・ファイルを置く」に今の振込額を入れる → 差がある人の「理由の見当」を見て、分かったことを理由のメモに書く
4. **元請との突合**（`/reconcile?m=YYYY-MM`）：元請ごとに支払通知のファイルを置いて「取り込んで突き合わせる」→ 結果の画面で「どの案件のことか決まっていない行」があれば案件を選ぶ → 差の一覧を見る → 「問い合わせ文を作る」で下書きを見る。**「問い合わせ済み」にはしない**（送るかどうかはお客様が決める）
5. **見張り番**（`/watch?m=YYYY-MM`）：赤・黄・お知らせを見る。**お試しで受け取っていない記録（口座・取引条件の明示・登録番号の確認日など）が無いことから出た指摘は、報告書に入れない**（受け取っていないだけなので）
6. **利益**（`/profit?m=YYYY-MM`）の「会社がかぶる消費税（免税の方への支払）」で、免税の方の分の会社の負担を見る（原則課税の会社だけ）
7. **PDF にして `private/C001/` に保存する**（印刷の画面で「PDF に保存」）
   - 並行運用レポート：「Excel と比べる」の右上の **「印刷用の報告」**（`/parallel/report?m=YYYY-MM`）
   - 突合レポート：「元請との突合」の右上の **「3か月のレポート」**（`/reconcile/report?from=YYYY-MM&to=YYYY-MM`。お試しは 1 か月分）
   - 問い合わせ文の下書き：突合の結果 →「問い合わせ文を作る」→「件名と本文をコピー」してテキストで保存
   - 見張り番：画面を印刷（事実だけを写すために使う。報告書にそのまま付けない）
8. **報告書**：下の頼み方で、AI に 10 のひな形で作ってもらう → 社長が読んで送る → 30 分の説明（録画）
9. **消す**：報告書を渡した日から **30 日以内に `private/C001/` をフォルダごと消す**（受け取ったファイルと db）。消した日をカレンダーに入れ、消したらお客様にメールで知らせる

うまく動かないとき（取り込めない形・読めないセル）は、画面の日本語の説明（番地つき）をそのままメモし、AI に「製品の取り込みでこう出た。どうする？」と聞きます。

```text
【お客様の番号 C001】のお試しの報告書を作って。sales-kit/10-diagnosis-report-template.md の「お試しの報告書」の形で。
- 材料：side-business/private/C001/ にある並行運用レポート・突合レポート・問い合わせ文の下書き・見張り番の画面と、私のメモ【貼る】
- 最初に、材料に名前・口座・住所・免許が入っていないか確かめて。あれば作業を止めて知らせて。
- 数字は材料から写すだけ。足し算・計算し直しはしない。材料どうしで合わないところがあれば、私に聞いて。
- 10 の「書き方の決まり」を守る（少ない可能性・原因の候補・事実と根拠だけ・判断は税理士と弁護士に）。
- お試しで受け取っていない記録（口座・取引条件の明示など）が無いことから出た見張り番の指摘は入れない。
- 30分の説明で見せる順番と、本契約に進むときの見積（お試しの費用を初期費用から差し引く）も作って。
```

## 4. 月に 1 回・節目にやること

- **月初**：先月の数字（3-12）と FAX の見出し（3-11）。製品のデモ（{製品のデモの URL}）を 1 回開き、架空の会社ができるか確かめる
- **月末の締めのとき**（会社の承認を得ている場合だけ）：自社の月末の締め作業にかかった時間を記録する。あとで「例」として使える実測の数字になる。使う前に会社に確認する（→ 02 の別紙 7）
- **3 か月ごと**：会社への報告（→ 02）。AI に「会社への報告を 02 の形で作って」と頼む
- **3 か月目・6 か月目**：続けるか変えるかを決める（→ 13）

## 5. やらないこと

- 商談を 1 週間に 3 件以上入れない（予約の枠は週 2 枠）
- AI の下書きを読まずに送らない
- 停止の申し出を翌日に回さない
- 会社のパソコン・スマホ・メール・勤務時間を使わない
- 無料の相談で、税金・法律の判断を言わない（「税理士・弁護士に」と伝える）
- お試しの報告を、製品のデモ（架空の会社）で作らない。お客様から受け取ったファイルそのものを、デモや AI のサービスに入れない（AI に渡すのは、製品が作ったレポートと自分のメモだけ。名前・口座・住所が入っていないことを先に確かめる）
