# しめ日ラボ（製品）— お客様に納める「月末の締め」の仕組み

業務委託ドライバーに支払う会社（5〜50 人ほど）の、月末の締めをまとめて引き受ける Web アプリです。
**お客様 1 社ごとに、お客様の Vercel ＋ Postgres に置きます**（データはお客様のもの）。全部の表に `tenant_id` があるので、将来は 1 つにまとめて提供（SaaS）にも切り替えられます。

- 何を・なぜ・どこまで：[`SPEC.md`](SPEC.md)（需要の証拠・既存との違い・デモの台本・受け入れ条件・言ってはいけないこと）
- 作りの決まり：[`ARCHITECTURE.md`](ARCHITECTURE.md)（機能を足す人向け）

## できること（画面）

| 画面 | 中身 |
|---|---|
| 今月の締め（ホーム） | 取り込み → 見張り番 → 明細 → 振込 → 締め の進み具合と「次にやること」。見つけたお金・未解決の質問 |
| 取り込み `/import` | 今の Excel・CSV をそのまま置く。列の意味を当て、形を覚える（翌月から 1 クリック）。名前の表記ゆれを覚える。ファイルの合計と照合。取り消しできる |
| 稼働と調整 `/work` | 月の稼働（ドライバー × 案件）の手直しと、その月だけの足し引き |
| 見張り番 `/watch` | 締める前に、記録から分かることを赤・黄で（取引条件の明示・60 日・合意の無い控除・振込手数料・経過措置・口座なし・急な増減 など）。根拠と出典つき。**判定はしない** |
| 取引条件の明示 `/terms` | 台帳から明示書を作り、ドライバーへリンクで渡して「受け取りました」を残す |
| 支払明細 `/statements` | 仕入明細書の記載事項を載せた明細と PDF。ドライバーへ署名つきリンク（ログイン不要）。「確認しました」・行ごとの質問・版の履歴 |
| 振込データ `/transfer` | 全銀の総合振込データ（振込はお客様が行う）。実際に振り込んだ日の記録 |
| 締め `/close` | 月を締める（DB でも書き換えを止める）。オーナーだけが理由つきで外せる。操作の記録 |
| Excel と比べる `/parallel` | 今の Excel の振込額と並べて、差と原因の候補を出す（並行運用）。全員が一致か説明済みになったら本番へ |
| 元請との突合 `/reconcile` | 元請の支払通知を置くと、自社の記録と比べて差を金額で。丁寧な問い合わせ文の下書き。3 か月のレポート |
| 利益 `/profit` | 案件・元請・ドライバー別の利益と推移、経過措置の負担、社長の 1 枚（PDF） |
| 会計ソフトへ `/export` | 弥生会計のインポート形式（既定）・マネーフォワードの仕訳帳・汎用 CSV（**取り込む前に税理士さんと勘定科目・税区分を確かめる**） |
| 設定 `/settings` | 会社・ドライバー・元請・案件・人ごとの単価・控除のルール・利用者・自分のパスワード・ヘルプ |

役割：オーナー（すべて・利用者の管理・締めの解除）／事務（登録・取り込み・明細・振込・締め）／閲覧（見るだけ）。ドライバーはログインしない（リンクだけ）。

## お客様 1 社を立ち上げる（1〜2 時間）

### 1. お客様に用意してもらうもの
- **Vercel のアカウント**（商用なので **Pro プラン**。無料の Hobby は商用で使えません）。こちらを「メンバー」に招待してもらうか、Vercel のトークンを発行してもらう
- **Postgres**：Supabase か Neon（どちらも東京リージョンあり）。接続文字列（`postgres://…`）をもらう。**バックアップ（日次）が有効か**を確かめる
- 請求はお客様のアカウントに直接かかります（当方は立て替えない）

### 2. 置き場所を作る（1 回のコマンド）
製品のコードは **オーナー個人の GitHub リポジトリ** に置いてある前提です（`side-business` を個人のリポジトリへ移す手順はサイトの README）。

```bash
cd product
DATABASE_URL='postgres://…（お客様の DB）' VERCEL_TOKEN='…' \
  npx tsx scripts/provision.ts --client "Sample Unso" --repo 自分のアカウント/shimebi --root product [--team team_xxx]
```

これで ① DB にマイグレーション ② Vercel にプロジェクト（リポジトリとつなぐ）③ 環境変数（`DATABASE_URL`・`APP_SECRET`・`SETUP_TOKEN`）④ 本番のデプロイ ⑤ **最初のオーナーの登録リンク**（`/setup?token=…`）の表示 までを行います。先に `--dry-run` で中身を確かめられます。

- 秘密の値はコマンドの引数に書かず、環境変数で渡します（履歴に残さない）
- Vercel のプロジェクト設定で **「Include source files outside of the Root Directory」が有効** になっていることを確かめてください（計算の部品を `../lib` から読むため。新しいプロジェクトでは既定で有効）
- 以降のデプロイでは、ビルドの前に `vercel-build`（`scripts/migrate.ts --if-configured`）が **マイグレーションを自動で当てます**

### 3. お客様と最初の午後（一緒に画面を見ながら）
1. 登録リンクをお客様の社長だけに渡し、オーナーとして登録してもらう
2. 「最初の設定」（ホームの帯から）：会社の基本 → ドライバー（Excel から貼り付け）→ 元請と案件 → 控除のルール → 取引条件の明示 → 先月の Excel → Excel と比べる
3. 先月分で明細を作り、今の Excel の振込額と比べる（並行運用）。差があれば原因の候補を一緒に見て、ルールを直す
4. 2 か月続けて全員が一致（か説明済み）になったら「本番に切り替える」

### 4. 毎月の保守（月額に含むもの）
- 製品を直したら個人のリポジトリへ push → 各お客様の Vercel が自動でデプロイ（マイグレーションも自動）
  - **お客様へ出す版は `release` ブランチ** にしておくと安全です（Vercel の Production Branch を `release` に）。`main` で確かめてから `release` へ
- 制度の変更（経過措置の段・源泉の率）は `../lib/payroll/tax.ts`・`../lib/engine/withholding.ts` の表を直すだけで全社に効きます
- お客様がやめるとき：オーナーが「データの書き出し」（`/data`）で全データを ZIP で持ち帰れます

## デモを公開する（商談とサイトの「デモを触る」）

デモは **来た人ごとに架空の会社を 1 つ作り、24 時間で消えます**（ほかの人の操作は見えない）。ログインは要りません。

1. **Neon か Supabase の無料の Postgres** を 1 つ作る（デモ専用。お客様のものと分ける）
2. オーナー自身の Vercel（Pro）で、同じリポジトリから別のプロジェクトを作る：
   ```bash
   DATABASE_URL='postgres://…（デモ用）' VERCEL_TOKEN='…' npx tsx scripts/provision.ts --demo --repo 自分のアカウント/shimebi --root product
   ```
   （環境変数に `DEMO_MODE=1` が入ります。`SETUP_TOKEN` は入りません）
3. 出てきた URL の `/demo/start` が入口です。サイトの環境変数 `NEXT_PUBLIC_PRODUCT_DEMO_URL` にこの URL を入れると、サイトの「製品のデモを触る」がここにつながります

PGlite（DB なし）のままでは、サーバーが複数に分かれる Vercel ではデモの会社が消えることがあるので、**デモにも Postgres を使ってください**。

## 環境変数

| 名前 | 必須 | 中身 |
|---|---|---|
| `DATABASE_URL` | 本番 ◯ | お客様の Postgres（`postgres://…`）。無ければ PGlite（手元・テスト用） |
| `APP_SECRET` | 本番 ◯ | 32 文字以上のランダムな値（ドライバーのリンクの署名）。**変えると発行済みのリンクがすべて使えなくなる** |
| `SETUP_TOKEN` | 本番 ◯ | 最初のオーナーの登録（`/setup?token=`）の合言葉。登録が済めば `/setup` は開けなくなる |
| `DEMO_MODE` | デモだけ | `1` で来た人ごとの架空の会社 |
| `DEMO_READONLY` | 任意 | `1` でデモの保存を止める（ふだんは不要） |
| `PGLITE_DIR` | 任意 | 手元の PGlite の置き場所（`memory` で揮発） |
| `NEXT_PUBLIC_SUPPORT_EMAIL`・`NEXT_PUBLIC_SUPPORT_LINE_URL` | 任意 | ヘルプの画面に出す、問い合わせ先 |

## 開発する人向け

```bash
cd side-business && npm install        # 計算の部品（../lib）の型のため
cd product && npm install
npm run dev                            # http://localhost:3300（PGlite。最初は /setup で会社を作る）
DEMO_MODE=1 npm run dev                # デモ（/demo/start）
npm run check                          # 型・Lint・テスト・本番ビルド
npm run test:e2e                       # ブラウザでの確認（375px・320px とパソコン）
npx tsx scripts/make-samples.ts        # 取り込みの見本ファイル（public/samples）を作り直す
npm run db:generate -- --name 名前     # 表を変えたらマイグレーションを作る（db/migrations）
```

- テストは PGlite（メモリの中の Postgres）で動くので、外の DB は要りません
- 締めた月の稼働・調整・明細、明細の版、操作の記録は **DB の引き金でも** 書き換えを止めています（`db/migrations/0001`・`0003`・`0005`・`0006`・`0008`）

## 気をつけること
- 見張り番・明細・問い合わせ文は **「記録から分かること」と「確認をおすすめ」まで**。適法・違反・税務の結論は出しません（`SPEC.md` の「言ってはいけないこと」。テストでも確かめています）
- 会計ソフトの取り込みの形式・税区分の名前は **体験版で取り込めたことを確かめるまで「対応」と言わない**
- 取適法・フリーランス法の数字（しきい値・日数）は、法改正や公取委の資料で変わったら `server/features/watch/rules.ts` を直します
