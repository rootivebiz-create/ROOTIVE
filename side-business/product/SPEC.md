# しめ日ラボ 製品仕様（SPEC）

- 作成日：2026-09-23（インボイスの経過措置が 80% → 70% に下がる 2026-10-01 の 8 日前）
- 対象：業務委託ドライバー 5〜50 人の軽貨物・運送会社。お客様ごとに Vercel ＋ Postgres へ置く（データはお客様のもの）。構築と立ち上げは当方が手伝う
- 料金（`site.config.ts` の `PLANS` が正。画面・資料に数字を直書きしない）：先月分でお試し 5 万円／支払明細パック 初期 25 万円＋月 1.8 万円／利益まるごとパック 初期 48 万円＋月 3.5 万円（いずれも税抜）
- 作りの決まりは `ARCHITECTURE.md`、表は `db/schema.ts`。この SPEC は「何を・なぜ・どこまで作れば完成か」を決める

> **ひとことで**
> 先月の Excel を置くだけで、今の計算と 1 円まで合うかを確かめてから乗り換えられる月末の締め。
> 元請の支払通知とのズレは円で出し、問い合わせ文まで作る。払いすぎ・合意の無い控除・10 月からの消費税の負担増は締める前に止める。
> ドライバーはアプリ不要。リンクで明細を開き「確認しました」を押す。その記録が、明細を仕入明細書として使うときの相手方の確認になる。

### この SPEC で決めたこと（依頼の割り振りからの変更）

| 変更 | 理由 |
|---|---|
| **元請の支払通知との突合の「中心部分」を P1 から P0 へ上げる**（取り込み・4 種類の差・円の合計・問い合わせ文の下書き・状態）。回収額の台帳・PDF の読み取り・3 か月まとめの追いかけは P1 に残す | (1) 運送向けで扱う製品が見つからなかった。入金を増やす方向に働く機能もこれだけ（feature-matrix、確度 中）。(2) 初期 25〜48 万円を、初期費用なしで月 1.1〜5.3 万円のコムトラックに対して説明できる材料は「取り戻したお金」しかない。(3) デモの一番の見せ場とお試しの納品物がこれに頼る。(4) 取り込み（`mapping_profiles.kind=payment_notice`）と表（`payment_notices` / `payment_notice_lines` / `reconciliation_items`）はもうあるので、足す手間が小さい |
| **売り方は変えない**：突合を毎月の仕事として使うのは利益まるごとパック。お試しでは当方が過去の分を 1 回だけ流す | `PLANS` の中身の変更は代表が決める。お試しの `includes` に「元請の支払通知があれば突き合わせ」を足すかは **代表の判断待ち** |
| **経過措置（日付で割合を変える計算）を P0 の明細と見張り番に含める** | 8 日後に 70% に下がる。会社の負担を今すぐ円で見せられる |
| **社長の「払ってよいか」確認を分ける**：振込先の変更の表示は P0（全銀の画面）、承認の流れは P1 | 振込先のすり替えを止める表示は安く作れて効き目が大きい。承認を必須にする流れは、利用者が 2 人以上の会社でないと意味がない |

### 1-4. 法令が「記録」を求めている（製品が役に立てるところ）

- **仕入明細書の相手方の確認**：会社が作る明細は、ドライバーが確認して初めて仕入税額控除の根拠になる。国税庁 インボイス Q&A 問86 は確認の方法として、(b) ネットで相手の端末に出し確認の通信を受ける、(c)「送付後一定期間内に誤りのある旨の連絡がない場合には記載内容のとおり確認があったものとする」と基本契約などで合意する、を認める https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/86.pdf （高）
- **取引条件の明示（フリーランス法 第3条）と支払期日（第4条：受け取りから 60 日以内。月締めは実務上「2 か月以内」）**：公取委の Q&A は「〜まで」「〜以内」を期日と認めない。「請求書受領月の翌月末日」には指導している（高）
- **取適法（2026-01-01 施行）の取引記録の 2 年保存**、**電子取引データの保存**（訂正削除の記録が残るか、訂正削除ができない仕組み、または事務処理規程） https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/03-6.pdf （中〜高）

### 表から分かること

1. **どこにも無い（運送向けでは）**：②元請との突合、③確認の記録と行ごとの質問、⑤合意の記録つきの控除、④運送の月末の精算の中で動く見張り番。**売りはこの 4 つ**
2. **一部にある。やり方で差をつける**：①（コムトラックも Excel を取り込める。差は「元請ごとに形を覚える」「横に並んだ日付の表も読む」「Excel の計算から控除を読み取る」）、⑨（1 円単位の並行運用レポート）、⑦（ロイヤリティ・管理費を入れたあとの案件別・ドライバー別の利益）
3. **当たり前（無いと負ける。売りにはしない）**：⑧会計 CSV、明細と請求書を作ること、登録番号の確認、締め。全銀と監査ログは他社にあるか分からないので「標準でついています」と言う
4. **いちばんの「今ので十分」はコムトラック**。Excel の取込・手数料のルール・会計 CSV が初期費用なしでそろう。支払明細パックは ③④⑤ と「当方が立ち上げる・データはお客様のもの」を目に見える形で足さないと、値段で負ける
5. **いちばん速く動いている相手は K-LEDGE**（6 月に開始、7 月に AI を追加、無料プランあり）。k-ledge.jp/updates を毎月見る。突合に手を出してきたら、立ち位置（元請を確かめてから請求する）を言い直す

## 3. 5 分で「欲しい」となる瞬間（デモの台本）

- 前提：`DEMO_MODE=1`、架空の会社「しめ日運送（デモ）」、ドライバー 12 人・案件 3・元請 2、先月の fixture（稼働の Excel・今の振込額の Excel・元請の支払通知）。**実データは同意を得たときだけ使う**
- 道具：ノート PC（会社の画面）と、社長自身のスマホ（ドライバーの画面）
- 数字はすべて fixture から出た値を画面が表示する。**台本に書いた額は例**

| 時間 | 見せること | 言うこと（例） | 相手が感じること |
|---|---|---|---|
| 0:00–0:40 | 空の会社で質問 4 つ（会社名・ドライバーの締め日・支払日・登録番号）に答える | 「最初に聞くのはこれだけです」 | 設定の地獄が無い |
| 0:40–1:40 | 先月の稼働の Excel（日付が横に 1〜31 日と並ぶ形）をそのまま置く → 名前の確認 1 画面（「山田 太郎／ﾔﾏﾀﾞ」→ 同じ人）→ 12 人の明細が並ぶ | 「Excel の形は変えなくていいです。表記ゆれは一度答えれば来月から聞きません」 | 自分の Excel が読まれた |
| 1:40–2:20 | **Excel の計算を読み取った結果**：「ロイヤリティ 10%（12 人中 11 人一致）・管理費 5,000 円（稼働した月だけ）・佐藤さんだけ 8%」→ 押して採用 | 「設定画面は一度も開いていません」 | 自分の会社のやり方を分かっている |

## 4. 機能一覧

### 4-0. 全体の約束（すべての機能に効く）

- 計算は `server/calc/statement.ts` の `buildStatementDrafts` だけで行う。画面・PDF・CSV・レポートは同じ関数の結果から作る（数字がそろうことをテストで確かめる）

#### P0-2 Excel・CSV をそのまま取り込む（列の自動判定・元請ごとに形を覚える・二重の取り込みを止める）

- **目的**：打ち直しを無くす。2 か月目からは「置いて 1 クリック」にする。元請や自社の Excel の形は変えさせない
- **画面**：`/import?m=`（置き場 → 列の対応（推測済み）→ 名前の確認 → プレビュー → 反映）、`/import/history`（取り込みの履歴と取り消し）
- **受け入れ条件**
  1. xlsx と csv（Shift-JIS / UTF-8 は自動判定）を読む。fixture は 4 種類：A 縦長（ドライバー・案件・数量・日付）、B 横長（行がドライバー、列が 1〜31 日、結合セルの 2 段の見出し、末尾に合計行）、C 案件が列、D Shift-JIS の CSV。**すべてで見出しの行と合計行を自動で見つける**。A と D は手直し 0 で正しく当たる
  2. 列の意味（ドライバー・案件・数量・日付・単価・金額・支払額）を同義語の表から推測する。`header_signature` で対応を保存し、同じ形のファイルでは対応の画面を飛ばす（**アップロードから反映まで 3 クリック以内**）
  3. 名前は `server/names.ts`（NFKC・空白・かなとカナ・半角と全角・（株）など）で照合する。当たらない名前だけを「新しく作る／既存の〇〇と同じ人」の 1 画面で聞く。答えは `aliases` に残り、翌月は聞かない。12 人の fixture で、**手入力 0 のまま** ドライバー 12 人・案件 3 件ができる
  4. 読めないセルは番地つきの日本語で出す（例：`B23「１２O」は数字ではありません。英字の O の可能性があります`）
  5. プレビュー：行数・案件ごとの数量の合計・Excel の合計行との一致・先月との差（±30% を超える人は黄色）
  6. 同じファイル（ハッシュ）、または同じ月 × ドライバー × 案件 × 日付の重複を見つけたら「二重の可能性 ¥X」と出して止める。**同じファイルを 2 回反映しても数量は倍にならない**（テスト）
  7. 反映の前は `import_batches.status='draft'`。反映したあとも締めるまでは「取り消し」でその取り込みの全行を戻せる。締めた月には取り込めない（DB の引き金）
  8. 50 人 × 31 日の xlsx を 5 秒以内に読む
  9. 取り込みの種類（`mapping_profiles.kind`）：`work`・`payment_notice`・`bank_accounts`・`current_payout`（今の振込額）。口座は口座一覧の Excel か **先月の全銀の総合振込ファイル**（120 バイト・Shift-JIS。読み取りを新しく作り、`zengin` の生成と往復のテストをする）からカナ名で当てる
- **法令の注意**：取り込んだ元のファイルは電子取引のデータになりうる。消さずに保存する（ファイルのハッシュ・名前・日時を `import_batches` に残す）。元請のファイルに個人情報がある場合、お試しでは番号に置きかえた形で預かる（`PLANS` の文言どおり）

#### P0-3 控除のルール（Excel の計算から読み取る・合意の記録を持つ）

- **目的**：ロイヤリティ・管理費・リース・保険の引き方は、事務の頭と Excel の数式の中にしかない。一から入力させず「あなたの Excel はこう計算しています。合っていますか？」と聞く。どの控除にも「いつ・どの書面で合意したか」を持たせる
- **画面**：`/rules`（ルールの一覧・人ごとの例外）、取り込みの中の「控除の提案」、`/terms`（取引条件の記録と明示書）
- **受け入れ条件**
  1. 控除の列を見出しの辞書（ロイヤリティ・管理費・事務手数料・リース・車両代・保険・燃料・立替・振込手数料）で見つけ、値から種類を提案する：全員で「委託料 × 率」が合えば `percent`、稼働した月だけ同じ額なら `fixed`（`onlyWhenWorked`）、数量 × 単価なら `per_unit`、一部の人だけ違えばその人だけのルール。数式が残っていれば数式も読む（`=E5*0.1` → 10%）
  2. 提案ごとに「この式で 12 人中 12 人一致」を出し、1 クリックで採用できる。fixture（10%・5,000 円・1 人だけ 8%）で 3 つの提案が正しく出る
  3. 採用したルールは `agreedInWriting=false` で作る → 見張り番が「合意の記録が見つかりません」と出す（明示書につなぐ）
  4. **振込手数料の列は控除のルールにしない**。見張り番の対象にする
  5. 区分：ロイヤリティ／管理費／リース／保険／立替の精算／事故・破損の負担／違約金・ペナルティ／その他。どれも `agreed_on` と `basis` を持つ。足したり額を変えたりすると `audit_log` に前後の値が残る
  6. **取引条件の記録**（新しい表 `terms_records`：driver_id・version・issued_on・内容の写し・sent_at・received_at・みなし確認の条項の有無・再委託の 3 項目）。台帳の単価と控除から明示書を作る（`@/lib/tools/torihiki-joken` を使う）。明細と同じ署名つきリンクで渡し「受け取りました」の日時を残す。A4 で印刷できる
  7. 明示書に、給付の内容、報酬の額または算定方法、具体的な支払期日、委託した日、給付を受け取る日または期間、場所、控除ごとの額または式、が入っている（ラベルの有無を単体テストで確かめる）
- **法令の注意**：フリーランス法 第3条（明示）・第5条（減額の禁止など。1 か月以上の委託が対象と記憶。**原文で確認する**）。合意があっても減額が許されるとは限らない。振込手数料は合意があっても認められない。「合意の記録があるので適法」とは言わない

#### P0-4 支払明細（仕入明細書の記載事項）と PDF

- **目的**：ドライバーが請求書を出さない運用で、会社が作る明細を仕入明細書として使えるようにする。控除の 1 行ずつに「なぜ」を載せる
- **画面**：`/statements?m=`（一覧・状態の件数）、`/statements/[id]`（中身・版の履歴）、PDF の出力
- **受け入れ条件**
  1. 記載事項がそろっていることを単体テストで確かめる：作った会社の名前、ドライバーの氏名と登録番号（ある場合）、取引の年月日（期間でよい）、内容（案件 × 数量 × 単価）、**税率ごとの合計と適用税率**、**税率ごとの消費税額**。免税の方には「消費税相当額」と書く
  2. 消費税の端数処理は **1 明細・税率ごとに 1 回**（行ごとに丸めない。テスト）
  3. ロイヤリティ・管理費など会社の売上になるものは、**相殺する前の金額とその消費税**を委託料と分けて書く
  4. 日付つきの稼働があれば、日ごとの数量を折りたたみで出す
  5. 経過措置：締め期間が段の境目をまたぐとき（例：9/21〜10/20）は、日付つきの稼働を日ごとに 80% と 70% に分け、会社の控えに「9/21〜9/30 ¥X（80%）／10/1〜10/20 ¥Y（70%）」と出す。日付の無い行が境目をまたぐときは按分せず、見張り番 `TRANSITIONAL_SPAN`（黄）へ回す
  6. 作り直すたびに、中身が変わったときだけ `version+1` とハッシュを付ける（`generateStatements`）。前の版は新しい表 `statement_versions`（追記のみ）に残す。純関数 `diffSnapshots(a, b)` が「数量 212→215 +¥450」「控除『リース』追加 −¥20,000」の形で差を返す
  7. PDF は A4 で 1 人 1 枚から。日本語フォントは `registerPdfFonts()`。画面と PDF の金額が一致する（テスト）
  8. 口座番号は下 3 桁だけ出す
- **法令の注意**：「仕入明細書として使える形」までを言う。「仕入税額控除できます」とは言わない。記載事項は国税庁の資料で**リリース前にもう一度確かめる**

#### P0-5 ドライバー専用リンク：スマホの明細・「確認しました」・行ごとの質問

- **目的**：ドライバーに何も入れさせず、パスワードも作らせない。会社は確認の記録を持ち、電話や LINE の問い合わせが減る
- **画面**：ドライバー `/s/<token>`（ログイン無し）。会社 `/statements?m=` の状態の列と、`/inbox`（質問の一覧）
- **受け入れ条件**
  1. token は `signStatementLink`（明細 id・`link_nonce`）。`link_nonce` を作り直すと古いリンクは 404 で「会社に新しいリンクをお尋ねください」。明細 id を別の人のものに書き換えた token も 404
  2. 応答のヘッダー：`X-Robots-Tag: noindex`、`Cache-Control: private, no-store`、`Referrer-Policy: no-referrer`
  3. 375px の表示順：**振込予定日と振込額（大きく）** → 案件ごとの数量 × 単価 → 日ごとの内訳（あれば）→「引かれているもの」（控除ごとの名前・式・合意した日・書面の名前）→ 消費税と経過措置の説明 → 版の番号。先月との比べ。過去の明細も同じ人のものなら見られる
  4. 「確認しました」：現在の version と hash が一致したときだけ保存し、古い版なら「明細が新しくなっています」で断る。保存するもの：statement_id・version・hash・確認時の振込額・日時・ip のハッシュ・UA。同じ版で 2 回押しても 1 件
  5. 明細が新しい版になったら、前の版の確認は「旧版を確認」と出し、新しい版は未確認に戻して帯で知らせる
  6. 行ごとの「ここを質問」：`lineKey`（案件・控除・調整・全体）を選び 1,000 字まで。回数の制限あり（`tooMany`）。事務の側に未読の数。返事と「解決」は同じリンクに出る。**締めたあとも確認と質問はできる**
  7. 送った日時（「LINE で送る」「SMS」「メール」「コピー」のどれかを押したとき）と、初めて開いた日時を記録する。開いたことは `audit_log` に `statement.view` として残す
  8. 純関数 `trustStatus(stmt, confirmations, messages, terms, now, deemedDays)` が 未送付／未読／既読／確認済み／質問あり／**みなし確認**／旧版を確認 のどれかを返す（状態ごとに単体テスト）。みなし確認は **3 つすべて** がそろったときだけ：送ってから `deemedConfirmDays`（既定 7）日が過ぎた・未解決の質問が 0・その人の取引条件の記録に「みなし確認の条項あり」。1 つでも欠けたら「未確認」
  9. 会社の一覧に「未送付・未読・既読・確認済・みなし確認・質問あり」の件数。確認の記録を CSV で出せる（`/api/export/confirmations?m=`：月・ドライバー・版・ハッシュ・振込額・送付・初回閲覧・確認・状態）
  10. 任意の設定で、開くときに電話番号の下 4 桁を聞く（共用のスマホ向け）。**現状：まだ作っていない**（任意。最初のお客様のドライバーがスマホを共用しているときに作る：会社の設定 ＋ /s と /t で聞いて短い間だけのクッキー、`tooMany` で回数を制限）
- **法令の注意**：国税庁 Q&A 問86 の方法 (b)・(c) に沿った記録を残す、までを言う。「これで仕入税額控除は大丈夫」とは言わない。確認は強制しない（押さなくても不利にしない）

#### P0-6 全銀の振込データ（振込先の変更を必ず見せる・期日との比較）

- **目的**：最後に残る手作業である振込の手打ちを無くす。口座の誤りによる組戻しと、支払の遅れを防ぐ
- **画面**：`/transfer?m=`（作る前の点検 → 出力 → 実際に振り込んだ日の入力）
- **受け入れ条件**
  1. 総合振込（120 バイト・Shift-JIS・ヘッダー／データ／トレーラー／エンド）を `buildZenginRecords` と `validateTransfers` で作る。**合計が対象の明細の振込額の合計と 1 円まで一致**（テスト）
  2. 口座・カナの不備がある人を一覧で出して止める（その人だけ外して作ることもできる）
  3. **前回の振込から口座が変わった人**を、変えた人と日時つき（`audit_log` から）で必ず出す
  4. 振込指定日が支払期日より後なら赤
  5. 振込手数料は会社持ちが既定。`transferFeeBearer='driver'` にすると見張り番が必ず赤
  6. 作る前に、未解決の質問・未確認の明細・旧版を確認したままの明細を一覧で出す（止めずに知らせる）
  7. `transfer_batches.executed_on` を入れると、明細ごとに「期日内／n 日遅れ」を出す（例：支払期日 2026-10-30・実行日 10-31 →「1 日遅れ」。テスト）。翌月の見張り番に `LATE_PAYMENT_PREV` として出る
- **法令の注意**：当方はお金に触れない（振込を行うのはお客様）。「期日内に払えます」とは言わない。記録と比較を出すだけ

#### P0-7 締めと監査ログ

- **目的**：締めた月は誰にも書き換えられない。誰がいつ何をしたかを、税務調査や元請の監査ですぐ出せる
- **画面**：`/close?m=`（残りの作業 → 見張り番 → 締める）、`/audit?m=`（月ごとの操作の記録）、`/records`（明細の検索：期間・金額の範囲・ドライバー、どの版も開ける。索引は CSV。版の写しから探すので、作り直しで消えた明細も見つかる）
- **受け入れ条件**
  1. 締めた月の `work_entries`・`adjustments`・`statements` への INSERT／UPDATE／DELETE は `MONTH_CLOSED` で止まる（UPDATE で月を動かすケースもテスト）
  2. `statement_versions` と `audit_log` への UPDATE・DELETE は引き金が断る（SQL テスト）
  3. 締めの解除は owner だけ。5 字以上の理由が必要。`month.reopen` を残す。解除して作り直すと版が上がり、古い版は残る
  4. 確認済みにしていない赤が残っているときは、owner が理由を書かないと締められない（staff は締められない）
  5. 締めるときに、その月の締めにかかった分数を任意で入れられる（`month_closes.minutes_spent`。§9 の物差しに使う）
  6. 記録する操作：取り込み・取り消し・ルールの変更・明細の作成・送付・確認・質問・見張り番の確認済み・振込データの出力・締め・解除・問い合わせ・書き出し

#### P0-10 元請の支払通知との突合（中心部分）※P1 から上げた

- **目的**：元請から入るべきお金の取りこぼしを見つける。立ち位置は「元請の数字を自社の実績で確かめてから請求・入金確認する」（K-LEDGE の「通知を請求書に変換する」の逆）
- **画面**：`/reconcile?m=`（元請ごとの差の合計 → 行の一覧 → 問い合わせ文）
- **受け入れ条件**

  2. 案件（別名・全角半角・空白・記号を無視）×（列があれば）ドライバーの単位で、自社の実績（数量 × 受注単価）と並べる

  5. 元請の締め日（`clients.closing_day`）が月末でなく稼働に日付があれば、その締めの期間（例：21 日〜20 日）で比べる。日付が無ければ「締め日が違うため月単位で比べています」と注記する
  6. 待機料・積込・再配達・高速代・燃料サーチャージは案件として登録でき、同じように比べる
  7. 「問い合わせ文を作る」：期間・案件・当社の実績・貴社の通知・差額の表と合計、確認のお願いを丁寧語の下書きにする。コピーと PDF。禁止語（違反・不当・法令名で責める言い方）が出ないことをテストで確かめる
  8. 状態：`open` → `asked`（日付）→ `resolved`（回収額を入力）または `accepted`（受け入れる。理由のメモが必須）。`asked` から 14 日で「返事待ち n 日」を黄色。表に `recovered_amount`・`asked_at`・`resolved_at` を足す
  9. デモの fixture（未払い 1・単価違い 1・数量違い 1）で 3 件と合計が画面と PDF で一致（E2E）。**現状**：見本の通知は「数量違い・単価違い・お支払通知にだけある行（待機料）」で、未払いの行は無い。`e2e/demo.spec.ts` は少ない可能性の 2 件（¥81,700・¥10,000）と合計 ¥91,700 を、結果の画面・問い合わせ文・その PDF で比べている
- **売り方**：毎月の突合は利益まるごとパック。お試しでは当方が過去の分（あれば 3 か月まで）を 1 回流して「見つかった額」をレポートに入れる（`PLANS` を変えるかは代表の判断待ち）
- **法令の注意**：受け取る側として、元請の支払の 60 日・手形・手数料の差し引き・一方的な減額は「確認をおすすめ」までに留める。**「未払いです」と断定しない**（「少ない可能性があります」）。送るかどうかは人が決める。「Gメンに通報しましょう」とは言わない

## 5. 親切の約束

### 社長
1. 最初の画面は「今月は払ってよいか」と「今月の締め、残り n 件」。法律の言葉は折りたたみ、専門用語は言い換える（経過措置 →「免税の方への支払で、会社がかぶる消費税」）
2. 数字は円で出す。**確定と見込みを分け、盛らない**。裏付けの無い数字（平均の回収額・削減時間の推測）は出さない
3. 「違反です」とは言わない。事実・根拠・次にやることだけ。判断は社長と専門家に残す
4. 振込先の変更・大きな増減・新しい控除は必ず目に入る場所に出す。月 1 分見れば眠れるようにする
5. 切り替えるかは並行運用レポート 1 枚で決められる。やめるときも取り込んだときと同じ形の Excel で持ち帰れる。データはお客様のサーバーにある

### 事務
1. Excel の形を変えさせない。画面には事務の Excel の見出し（例「個数」）をそのまま出す
2. 表記ゆれは一度答えれば覚える。2 か月目からは 3 クリック
3. 取り込みは締めるまでいつでも取り消せる。2 回置いても倍にならない
4. マスタを先に埋めなくても明細まで進める。足りないものは必要になった段で聞く。途中で閉じても続きから
5. 読めないセルは番地つきの日本語で言う
6. 見張り番の指摘には必ず「何が・いくら・どこを直すか（ボタン）・根拠」。直さないと決めたら理由を書いて確認済みにでき、同じ指摘を毎月繰り返さない
7. 質問は明細の行に紐づいて文字で届く。電話や個別の LINE を探し回らなくてよい。直したら版の違いの説明をシステムが書く
8. 問い合わせ文は下書きまで作る。元請との関係を壊さない丁寧語。送るかは人が決める
9. 並行運用のあいだも今の Excel の作業は 1 つも増えない
10. 誰がいつ何をしたかが残るので、休みや引き継ぎのときも進み具合が分かる

### ドライバー
1. アプリもパスワードも要らない。LINE・SMS・メールのリンクを押すだけ
2. 一番上に「いつ・いくら振り込まれるか」。大きな文字、375px で崩れない
3. 日ごとの数量を自分の控えと見比べられる。先月との比べもある
4. 「控除」ではなく「引かれているもの」と書き、1 行ずつ「なぜ・何 %・いつ合意したか」を出す
5. おかしい行はその行から質問でき、返事も同じ画面に出る。締めたあとも聞ける
6. 「確認しました」は 1 回押すだけ。押すことを強制しない
7. 口座は下 3 桁だけ。リンクは検索に出ず、会社がいつでも無効にできる。ほかの人の明細は見えない

## 6. 伸ばし方

### 6-1. 全業種へ
- 報酬の形（数量 × 単価・日額・時給・歩合・段階制・最低保証）と源泉徴収の区分は `side-business/lib/engine` を共有する。軽作業・建設の一人親方・美容・IT・講師など、ほかの業務委託にも「Excel を置くだけ → 明細 → 確認 → 見張り番 → 締め」の同じ流れで広げる
- 見張り番・確認・合意の台帳は業種に依らない。業種ごとに違うのは取り込みの同義語の表と、報酬の形の登録だけ
- 控除のルールの種類は計算の登録にする。足すときは純関数とテストを足すだけで、逆算の提案も同じ登録から出る

### 6-2. SaaS への切り替え
- **全表に `tenant_id`** がある。今は 1 社ごとに別の Vercel ＋ Postgres だが、同じ表のままひとつにまとめて提供する形へ移れる
- 移るときに足すもの：申込みと課金、テナントの作成、行単位の分離の確認（今の `eq(tenantId)` をすべての読み出しで守っていることをテストで確かめ続ける）
- お試しの診断レポートは本番と同じ関数から作る。成約後はその数字がそのまま最初の月の比較の基準になる

### 6-3. API・つなぎ口（どれも無くても本体は動く）
| 入口／出口 | P0 | 次の段 |
|---|---|---|
| 取り込み | xlsx・csv（`mapping_profiles.kind`） | PDF の読み取り、日報アプリの CSV、元請の API |
| 送付 | コピー・LINE 共有の URL・SMS・メール | LINE Messaging API での自動送付 |
| 登録番号 | 形と検査の数字・確認した日の手入力 | 国税庁の公表サイトの Web-API |
| 会計 | —（P1 で弥生・汎用） | freee（未決済の取引）・MF |
| 銀行 | 全銀ファイルの出力と読み取り | 入出金 CSV で入金と振込を確認 |
| 証跡 | 全データの書き出し | 種類ごとの出力を登録する証跡パック |
- 法令のルールは `{ code, 重さ, 根拠, 出典, 時点, 有効期間, check }` のデータ＋純関数。法改正は 1 ルール足すだけ。経過措置の 2028-10（50%）・2030-10（30%）は表だけで効く
- 確認の仕組みは「文書 × 版 × ハッシュ × 相手の操作（開いた・受け取った・確認した・質問した）」の汎用の部品にする。明細・取引条件の明示書・控除の同意書、将来は元請へ自社の実績を送って確かめてもらう向きにも使う
- 「見つけたお金」は突合・見張り番・並行運用の結果から集める。新しい機能も影響額を返すだけで社長の 1 枚に載る

## 7. 作らないもの

| 作らない | 理由 |
|---|---|
| 配車・シフト・点呼・アルコールチェック・日報（P0 では） | K-LINK（1 人 月 1,000 円）と K-LEDGE（無料枠）が押さえている。月末のお金と関係が薄い。別売りの運行記録オプションとして後で |
| ドライバー用のアプリ・ログイン ID | 入れてもらうこと自体が乗り換えの壁。署名つきのリンクで足りる |
| AI チャット・AI の法律・税務の相談 | K-LEDGE の URCHAT と比べられるだけで ROI を示せない。誤ったときの責任が重い。AI は P1 の PDF の読み取りだけ（同意つき） |
| 労働者に当たるか・偽装請負かの判定や点数 | 労基署の判断そのもの（ルートの指示・制服・報酬の天引きを理由に労働者と認めた例がある）。製品は控除を透明にするところまで |
| 免税ドライバーへの「下げた単価」の提案 | 減額・買いたたきのおそれ（財務省・公取委ほかの Q&A）。会社の負担額を見せるだけ |
| 振込の実行・銀行 API・早払い（ファクタリング） | お金に触れない方針。資金移動と貸金の規制。早払いはペイトナーの領分 |
| freee・MF の API 連携 | CSV で足りる。認証の保守が重く、お客様ごとの配置と相性が悪い |
| 認定タイムスタンプ・電子署名 | 問86 は確認の通知で足りる。電子取引の保存も訂正削除の記録か事務処理規程で満たせる |
| 保存期間を過ぎた記録の自動削除 | 保存の義務と食い違うおそれ。消すかは会社が決める |
| 貨物自動車運送事業法の書面交付・物流特殊指定の点検 | 軽貨物に当てはまるか、施行日はいつかが未確認。国交省の Q&A を確かめてから |
| 雇用している社員の給与計算・勤怠 | 業務委託の月末の締めに絞る |
| 複数社にまとめて提供するための課金・申込み | 今は 1 社ずつの構築なので要らない（§6-2 で移るとき） |

## 8. 言ってはいけないこと（must_not_claim）

画面・PDF・問い合わせ文・営業資料・サイト・口頭のすべてに当てはまる。画面と PDF と問い合わせ文は `tests/wording.test.ts` で機械的に確かめる。

### 法令・税務の判定
1. 「適法です」「違反はありません」「問題ありません」「対応済み」「これで調査・監査に対応できます」
2. 「勧告・指導を防げます」「Gメンが御社を調べに来ます」「公取委が軽貨物を狙っています」
3. 「ドライバーが合意しているので大丈夫」（振込手数料は合意があっても不可。減額は合意で正当にならない）
4. 「このドライバーは労働者です／ではありません」「偽装請負ではありません」
5. 「仕入税額控除できます」「税務上問題ありません」「電子帳簿保存法に完全対応」（言えるのは「仕入明細書の記載事項を載せる形」「国税庁 Q&A 問86 の方法に沿った確認の記録を残す」まで）
6. 「必ず合う」「法令に完全対応」
7. 登録番号の状態を、確認した日時なしで「有効です」と出すこと
8. 「フリーランス法と取適法のどちらが先に当たるか」を断定すること（出典が食い違う）
9. 取適法のしきい値・第5条の 1 か月・第16条の 6 か月と 30 日・物流特殊指定の改正日（2027-04-01？）を、原文で確かめる前に断定すること

### お金・効果
10. 平均の回収額・「必ず元が取れます」・削減時間の約束（お試しで実測した自社の事例だけを、同意を得て使う）
11. 「離職が減ります」（報酬と離職の関係の数字はあるが、明細を見せて離職が減るかは測っていない。言えるのは「問い合わせと揉め事が減る見込み」）
12. 突合で「未払いです」と断定すること（「少ない可能性があります」）
13. 「補助金が使えます」（IT 導入補助金などは登録済みのツールと支援事業者が前提。お客様ごとの構築が当てはまるかは未確認）
14. 「ドライバーの報酬を下げるべき」「免税の方の単価を見直しましょう」

### 他社との比べ方・数字の出し方
15. 「X 社にはこの機能がありません」「どこにも無い機能」（競合のページを開けていない。§2 の表は社内用）
16. 「運輸業がフリーランス法の違反で最多」（3 位。135 件）
17. 「K-LEDGE は無料」と料金を断定すること（料金ページを読めていない）
18. ドラピタ調査の 66.7% などを「運送会社の 3 分の 2 が」と言うこと（母数は取り組む企業の約 30 社と推定）。@IT の 89.4%・67.1% を「運送会社の」と言うこと（業種を問わない調査）。リクルートの 51.5% を「業務委託ドライバーの」と言うこと（含むか未確認）
19. 会計ソフトに「対応」と書くこと（体験版に取り込めた記録を残すまで）
20. 国のロゴ・「国税庁・公取委が推奨」のような公認をにおわせること
