# 運用ガイド（毎月の作業とメンテナンス）

ROOTIVE 利益管理システムを日々使うための手引きです。画面のどこを押すかまで書いています。
スマホでは画面下のタブ（**ホーム／稼働／支払／案件／設定**）、PC では左のメニューで移動します。画面上部の **「◀ 2026年9月 ▶」** が「稼動月」で、すべての画面がこの月に連動します（真ん中を押すと月の一覧から選べます）。

---

## 1. 毎月の流れ

```
月初        月中               月末〜翌月初                      翌月末
┃ 前月から複製 ┃ 稼働を入力（随時） ┃ 管理費・調整 → 警告確認 → 月締め ┃ 明細送付 → 弥生 CSV → バックアップ確認 ┃ 振込
```

### 1-1. 月初：前月から複製する

1. 稼動月を当月に合わせ、下タブ **「稼働」** を開きます。
2. **「前月から複製」** を押します。前月に稼働があった「ドライバー × 案件内容」の組み合わせが、**数量 0** で当月に作られます。
   - 単価・ロイヤリティ率・端数処理は **現在のマスタ**から取り直されます（前月の値のコピーではありません）。
   - 停止中のドライバー・案件・内容は複製されません。既にある組み合わせは飛ばされるので、何度押しても増えません。
   - 数量 0 のままの行はダッシュボードに「数量が 0 のままの稼働行」として警告が出ます（入力忘れ防止）。管理費は数量 0 の行しか無い月には計上されません。

### 1-2. 月中：稼働を入力する

**1 行ずつ入れる（スマホ向き）**

1. **「稼働」** → **「＋ 稼働を追加」**。
2. ドライバー → 案件（内容が複数ある案件は内容も）→ 数量（日給型は「稼働日数」、個数型は「個数」。テンキーで入力）。
3. 受注単価・支払単価・ロイヤリティ率・端数処理は自動で入ります（「自動」の表示）。特別な事情があるときだけ書き換えます（「手入力」表示になり、「マスタの値に戻す」で戻せます）。
4. 下のプレビュー（会社売上／ドライバー売上／単価差額利益／ロイヤリティ／行の利益）を見て **「保存」** または **「保存して続けて追加」**。
   - 支払単価が受注単価より高いと赤字の警告が出ますが保存はできます。
   - **新しい稼働行は数量 0 では保存できません**（「数量は 0 より大きい値を入力してください」）。数量 0 のまま置けるのは「前月から複製」で作られた行だけです。

**まとめて入れる（PC 向き）**

1. **「稼働」** → **「一括入力」**。
2. 案件内容を 1 つ選ぶと、稼働中ドライバー全員の数量欄が並びます。数量を入力して **「保存」**。
   - 既にある行は数量だけ更新（単価は入力時のスナップショットのまま）、**既にある行を空欄または 0 にするとその行は削除**、新しく入れた人は現在のマスタで作成されます。保存後に「追加 ○ 件／更新 ○ 件／削除 ○ 件」と表示されるので確認してください。

複製した行の数量を直すときは、行を押して **「編集」** → 数量を入れて保存します。

### 1-3. 月末：支払明細で管理費・調整を確定する

1. 下タブ **「支払」** を開くと、当月のドライバー一覧（ドライバー売上／ロイヤリティ／管理費／調整／支払額／会社利益）が出ます。
   - 稼働も管理費・調整も無いドライバーは一覧に出ません。**稼働のないドライバーに管理費や調整だけを登録したい**ときは、一覧の下にある **「この月に稼働のない稼働中ドライバー（○ 名）の管理費・調整を登録する」** を押して開き、名前のボタンを押すとその人の明細画面に移動できます（締め済み月では表示されません）。
2. ドライバーを押して明細を開き、**「管理費・調整を編集」**。
   - **管理費**：標準値（ドライバー設定の月額）が入っています。今月だけ違う場合は書き換え、**「標準に戻す」** で戻せます。稼働（数量 > 0）が 1 件も無い月は自動的に 0 で計算されます。
   - **調整**：**「調整を追加」** → 項目名／金額（**控除はマイナス**、加算はプラス）／**会社利益に計上するか**。
     - リース代相殺・ペナルティなど会社の収入になるもの → 計上する（チェック ON）
     - 立替精算・預り金の返金など会社の損益に関係しないもの → 計上しない（OFF）
   - ドライバー設定で登録した **固定控除** は毎月自動で入っています（初回の稼働作成時に複写）。無ければワンタップで追加できます。
3. 支払額のプレビューを確認して **「保存」**。

### 1-4. 締める前に：ダッシュボードの警告を確認する

下タブ **「ホーム」** の上部に、該当がある場合だけ警告が出ます。押すと該当画面に移動します。

| 警告（「確認が必要な項目」） | 意味 | 対処 |
|---|---|---|
| 支払単価が受注単価を上回る稼働行（赤字）が ○ 件あります | その行が赤字 | 単価の入力ミスか、意図した赤字かを確認 |
| 今月の管理費がドライバーの標準と異なります | 今月だけ違う額になっている | 意図したものか確認（例：相曽慧 14,999 → §8 オーナー確認事項 1） |
| 稼働中なのに今月の稼働がないドライバーが ○ 名います | 入力漏れの可能性 | 稼働を入力するか、退職なら停止中に |
| 数量が 0 のままの稼働行が ○ 件あります | 複製後の未入力 | 数量を入れるか、行を削除 |

川島幹太（オーナー本人）は支払単価 0・率 0%・管理費 0 が正常なので警告は出ません。
過去の月の締め忘れは、**設定 → 月締め** の一覧に黄色の **「未締め」** バッジで表示されます（月締めは 1-5）。

### 1-5. 月締め

1. **設定 → 月締め**。データがある月の一覧（件数／売上／利益／支払／状態／締め日時）が出ます。
2. 対象月の **「この月を締める」** → 確認 → 実行（管理者以上）。
3. 締めると次のことが起こります。
   - その月の稼働・管理費・調整は**編集できなくなります**（画面から編集ボタンが消え、データベース側でも拒否）。月セレクタに鍵マークと「締め済み」バッジが付きます。
   - 締め時点の集計スナップショットが保存され、**バックアップ JSON が Supabase の Storage に自動保存**されます（同じ画面の対象月の行にある **「バックアップ」** ボタン、または **設定 → データ** の「締め時バックアップ」一覧の **「ダウンロード」** で取り出せます）。
   - **ドライバーポータルにその月の明細が表示**されるようになります（締めるまでは「集計中」）。
   - 監査ログに「誰がいつ締めたか」が記録されます。

### 1-6. 明細を送る

**支払 → ドライバー** の明細画面から。

| 方法 | 操作 | 使いどころ |
|---|---|---|
| LINE テキスト | **「明細テキストをコピー」** → LINE に貼り付け | 一番手軽。会社利益は含まれません |
| PDF 明細 | **「PDF」** → ダウンロード → LINE・メールで送付 | 正式な明細。A4 縦・会社名・登録番号・振込予定日入り |
| 印刷 | **「印刷用ページ」**（新しいタブで開く）→ ブラウザの印刷 | 紙で渡す場合 |
| CSV | **「個人明細 CSV」** | Excel で確認したい場合 |
| ドライバーポータル | ドライバー本人にアカウントを発行（→ 3-1） | 本人がいつでも自分の締め済み明細・PDF を見られる |

振込予定日は会社設定の「翌月末」などのルールから自動計算され、明細に印字されます。

### 1-7. 弥生会計 CSV を税理士へ

1. 下タブ **「支払」**（支払明細ページ）の右上 **「弥生 CSV」**、または **設定 → データ** の「弥生会計 仕訳 CSV」の **「当月」**／**「全期間」** を押すと、仕訳データ（Shift_JIS、25 列、ヘッダー無し）がダウンロードされます。
2. 税理士に送るか、弥生会計の「仕訳日記帳 → インポート」で取り込みます。
3. 勘定科目（売掛金／売上高／外注費／未払金／雑収入／立替金）と税区分は **設定 → 会社設定 → 弥生会計の勘定科目** で変更できます。**初回は必ず税理士に確認**してください（§12 未決事項 2）。

### 1-8. バックアップの確認（月 1 回）

- **設定 → 月締め** の一覧で、締めた月の行に **「バックアップ」** ボタンが付いていることを確認します（**設定 → データ** の「締め時バックアップ」一覧にも並びます）。
- **設定 → データ → 「バックアップ JSON を保存」** で全データを手動でも保存できます。**月に 1 回は自分の PC や Google Drive にも保存**しておくことを勧めます。
- Supabase 無料プランは 7 日間アクセスが無いと一時停止しますが、Vercel の定期アクセス（毎日 6 時に `/api/cron/keepalive` を呼ぶ設定。`vercel.json`）で防いでいます。この定期アクセスは Vercel の環境変数 `CRON_SECRET` が設定されていないと動きません（Vercel → プロジェクト → Settings → Cron Jobs で直近の結果が 200 なら正常。503 なら [docs/SETUP.md](SETUP.md) 手順 8）。万一「Project is paused」と表示されたら Supabase ダッシュボードの「Restore project」を押します。
- 稼働・支払の CSV（当月・全期間）も同じ画面から出せます。Excel でそのまま開けます。

## 2. マスタ（設定）の変更

### 2-1. 単価の改定

- **設定 → 案件・単価** → 案件を押す → **内容の行**（内容名／区分／受注単価／支払単価）を書き換えて保存。
- **過去月の数字は変わりません。** 稼働行には入力時点の単価が記録（スナップショット）されているためです。改定後に作った稼働行から新しい単価になります。
- 当月にもう複製済みの行がある場合は、その行を開いて **「マスタの値に戻す」** を押すと新しい単価が取り直されます（一括入力の既存行は単価を維持するので注意）。
- 同じ案件で単価の違う仕事がある場合（宅急便 180/162 とネコポス 50/50 など）は、内容を分けて登録します。

### 2-2. ドライバー個別単価

- **設定 → ドライバー** → ドライバーを押す → **「案件内容ごとの個別支払単価」** に金額を入れる（空欄＝案件の標準単価）。
- 例：吉田雅一・高森豪介の三郷Amazon 支払 21,960（標準は 21,780）。
- 稼働の自動入力の優先順は「個別単価 → 案件内容の支払単価」です。

### 2-3. ロイヤリティ率・管理費・端数処理

- ドライバーごと：**設定 → ドライバー** で「ロイヤリティ率」「管理費（月額）」「端数処理（会社設定に従う／個別）」。
- 会社の既定：**設定 → 会社設定**（オーナーのみ）で「新規ドライバーの標準ロイヤリティ率・標準管理費」「ロイヤリティ額の端数処理の既定（初期は『丸めない』＝Excel と同じ）」。
- これらも**稼働行の作成時にスナップショット**されるため、変更しても過去の行は動きません。当月の既存行に反映したいときは行の「マスタの値に戻す」。管理費は「支払 → 管理費・調整を編集 → 標準に戻す」。

### 2-4. 案件・ドライバーの追加と停止

- 追加：**設定 → ドライバー** → **「ドライバーを追加」**、**設定 → 案件・単価** → **「案件を追加」**。名前は会社内で重複できません。並び順は一覧（PC の表）の **「並び」** 列にある **▲（上へ）／▼（下へ）** ボタンで変えられます。
- 停止：稼働行が 1 件でもあるドライバー・案件・内容は**削除できません**（過去の数字を守るため）。編集画面で状態を **「停止中」** にすると、稼働の追加候補・前月複製・一括入力から外れます。

## 3. ユーザーの追加・退職

### 3-1. ユーザーを招待する（オーナーのみ）

1. **設定 → ユーザー管理** → 右上の **「ユーザーを招待」**。
2. メールアドレス、表示名（任意）、ロールを選びます。「招待メールも送る」にチェックを入れるとメールも送られます（届くにはメール送信の設定が必要）。
   - **管理者**：登録・編集・月締め・出力ができる（事務担当など）
   - **閲覧者**：見るだけ＋CSV 出力（税理士など）
   - **ドライバー**：本人の締め済み明細だけ見える。**対応するドライバー**を必ず選びます
3. **「招待する」** を押すと「招待リンクを発行しました」の画面に **招待リンク**（`https://rootive-profit.vercel.app/invite/…`）が表示されます。**「リンクをコピー」** を押します。
4. **招待リンクを LINE で本人に送ります。** 本人がリンクを開いて「ログインして始める」を押すだけでログインでき、メールは不要です。
   - リンクは 7 日で失効・1 回限り。同じ画面の **「招待」** 一覧（未受諾の招待）で、いつでも **「リンクをコピー」**・**「メールを再送」**・**「リンクを再発行」**（古いリンクは無効になります）・**「取り消し」** ができます。
   - ログイン済みなのにパスワード未設定でメールも届かない人には、ユーザー一覧の **「招待リンク」** ボタンで新しいリンクを発行して送れます。ユーザー一覧の「最終ログイン」が **「未ログイン」** の人は、まだ一度もログインしていません。
5. ログイン後、本人に **アカウント画面**（右上のユーザーアイコン → アカウント。ドライバーは下タブ「アカウント」）で **パスワードを設定**してもらうと、次回から「メール＋パスワード」でログインできます（メールが届かなくても困りません）。

### 3-2. ロールの変更

**設定 → ユーザー管理** → ユーザーの **「ロール変更」**。ドライバーに変える場合は対応ドライバーを選びます。自分自身のロールは変えられません。

### 3-3. 退職・契約終了のとき

1. **設定 → ドライバー** → 該当ドライバーを **「停止中」** にします（削除はしません。過去の稼働が残るため）。
2. 本人にアカウントがある場合は **設定 → ユーザー管理** → **「無効化」**。無効化されたユーザーは即座に何も見られなくなります（後で「有効化」で戻せます）。**無効化すると、その人宛の未使用の招待リンクも同時に取り消されます**（リンクで再び有効になるのを防ぐため）。
3. 未受諾の招待が残っていれば、「招待」一覧の **「取り消し」**。

## 4. 締めの解除（訂正が必要になったとき）

締め済みの月を直すには、いったん締めを解除します。**オーナーのみ**できます。

1. **設定 → 月締め** → 対象月の **「締めを解除」** → 確認。
2. 稼働・支払明細を修正します。
3. 修正が終わったら **「この月を締める」** をもう一度押します。スナップショットとバックアップは新しいものに更新されます。

注意：

- 解除している間、ドライバーポータルではその月が「集計中」に戻り、本人から明細が見えなくなります。
- 明細や PDF を送付済み・弥生 CSV を税理士に渡し済みの場合は、**再度送付・差し替え**が必要です。修正前後の数字は監査ログ（設定 → 監査ログ）で確認できます。
- 解除・再締めはすべて監査ログに残ります。

## 5. バックアップ・復元・データ全削除

### 5-1. バックアップ

| 種類 | 場所 | 内容 |
|---|---|---|
| 締め時バックアップ（自動） | 設定 → 月締め → 対象月の「バックアップ」／設定 → データ → 「締め時バックアップ」→「ダウンロード」 | 締めた時点の全データ JSON（Supabase Storage の `backups` バケットに保存） |
| 手動バックアップ | 設定 → データ → 「バックアップ JSON を保存」（管理者以上） | 現在の全データ JSON（会社設定・ドライバー・案件・単価・稼働・管理費・調整・締め状態） |
| CSV | 設定 → データ（稼働 CSV／支払 CSV／弥生会計 仕訳 CSV の当月・全期間）／支払明細ページ（支払一覧 CSV・弥生 CSV・個人明細 CSV） | 稼働明細・支払一覧・個人明細・弥生仕訳（Excel 用） |

バックアップ JSON にはユーザー（ログイン情報）と監査ログは含まれません。

### 5-2. 復元（JSON 取り込み）

**オーナーのみ**。

1. **設定 → データ** の **「取り込み・復元（オーナー）」** カードで、「JSON ファイル」の **ファイル選択ボタン**を押してファイルを選びます（本システムのバックアップ JSON、または試作アプリの JSON。自動判別。15MB まで）。
2. **プレビュー**に件数と月別集計（売上／利益／支払）が出ます。**取り込む前に合計を検算**してください。
3. **「取り込みを実行」** を押し、確認ダイアログでもう一度 **「取り込みを実行」** を押します。
   - **ID が同じデータは上書き**、無いものは追加されます。**取り込みで削除はされません**（バックアップ後に追加したデータは残ります）。「バックアップ時点に完全に戻したい」場合は、先に 5-3 の全削除をしてから取り込みます。
   - 締め済み月のデータも復元のために書き換えられます（通常の編集とは異なり、締めガードを通過します）。
   - 別の会社のデータ（ID の衝突）は拒否されます。同じ名前のドライバー・案件が別 ID で既にあるとエラーになります（既存の名前を変えるか、取り込みデータを確認）。

### 5-3. データ全削除

**オーナーのみ**。稼働・支払・マスタをすべて消します。**元に戻せません。必ず直前にバックアップ JSON を出力してください。**

1. **設定 → データ** の一番下、赤枠の **「データ全削除（オーナー）」** カード。
2. 確認のため **会社名（株式会社ROOTIVE）を正確に入力**すると **「データを全削除」** ボタンが押せるようになります → 押す → 確認ダイアログの **「すべて削除する」**。
3. 消えるもの：ドライバー・案件・内容・個別単価・固定控除・稼働・管理費・調整・月締め・AI 分析。
   残るもの：会社設定・ユーザー・招待（ただしドライバー本人のユーザーは、対応ドライバーが消えるため「無効な閲覧者」になります。再招待で復帰）・監査ログ。

### 5-4. 初期データ投入（サンプル）

**設定 → データ** の **「初期データ投入」** カードは、**ドライバーが 0 件のときだけ表示**されます（全削除の直後や、初めてログインしたとき）。**「サンプル初期データを投入（§8.6）」** → 確認ダイアログの **「投入する」** で、ドライバー 10 名・案件 7 件・個別単価と（チェックを入れていれば）2026 年 9 月の稼働行 10 行が入ります。試作アプリの JSON がある場合は、こちらではなく 6. の取り込みを使ってください。

## 6. 試作アプリ（Claude 上の「ROOTIVE 利益管理」）からの移行

### 6-1. 準備

1. 試作アプリで **バックアップ JSON を書き出し**、ファイル（`rootive-backup-….json`）を用意します。
2. 試作アプリ側の月別合計（例：2026 年 9 月 売上 2,704,970／利益 621,506.8／支払 2,083,463.2）を控えておきます（検算用）。

### 6-2. 画面から取り込む（推奨）

順番は **設定 → データ → 「取り込み・復元（オーナー）」** です。

1. オーナーでログインし、**設定 → データ** の **「取り込み・復元（オーナー）」** カードで JSON ファイルを選びます（試作アプリ JSON も本システムのバックアップも同じ場所です）。
2. ファイルを選ぶと **「試作アプリ JSON」** と判定され、変換後の件数（ドライバー・案件・内容・稼働・月）と**月別集計（売上／利益／支払）**がプレビューされます。
3. プレビューの合計が試作アプリの数字と一致することを確認します。
   - 一致しない場合はまだ取り込まず、「注意」欄（不明なドライバー・案件、率や単価の欠落など）を確認します。「別のファイルを選ぶ」でやり直せます。
4. **「取り込みを実行」** → 確認ダイアログの **「取り込みを実行」** を押します。取り込み後、ダッシュボードで同じ月の数字を再確認します。
5. 試作アプリで「締め済み」だった月は、本システムでも締め済みとして取り込まれます。

同じファイルを**何度取り込んでも重複しません**（試作の ID から常に同じ ID を作る仕組み：uuid v5）。試作側でデータを直してもう一度書き出し、再取り込みすれば上書きされます。

### 6-3. コマンドで取り込む（CLI、開発者向け）

```bash
# 変換とプレビューだけ（DB には触らない）
npx tsx scripts/migrate-prototype.ts rootive-backup.json --out backup.json

# 本番 DB に直接取り込む（オーナーのメールで実行。DB URL は Supabase → Project Settings → Database → Connection string（URI）。DB パスワードが必要）
npx tsx scripts/migrate-prototype.ts rootive-backup.json --apply \
  --db-url "postgresql://postgres.xxxx:<DBパスワード>@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres" \
  --as rootive.biz@gmail.com
```

`--out` で書き出した `backup.json` は、画面の「取り込み・復元（オーナー）」からも取り込めます。

## 7. トラブル対応

### 7-1. 数字が合わない時のチェック順

支払明細の 1 行ずつ、次の順で見ると原因が見つかります。

1. **単価スナップショット**：稼働行の「受注単価」「支払単価」が、その時点の契約と合っているか。マスタを後から変えても行は変わりません（行を開いて「マスタの値に戻す」か手入力で修正）。個別単価（ドライバー設定）が入っているかも確認。
2. **ロイヤリティ率**：行の率（10% / 12.5% など）。ドライバー設定の率 → 会社の標準率の順で自動入力されます。行ごとに違うと明細の率表示が変わります。
3. **端数処理**：ロイヤリティ額は「丸めない（既定）／切り捨て／四捨五入／切り上げ」のどれかで、行ごとに記録されています。Excel の計算と合わせるなら「丸めない」。表示は整数に四捨五入されますが、CSV には生の値（小数）が出ます。
4. **管理費の計上条件**：管理費は「数量 > 0 の稼働行が 1 件以上ある月」だけ計上されます。稼働が 0 の月は 0 です。今月の額が標準と違う場合はダッシュボードに警告が出ます。
5. **調整の利益計上フラグ**：調整の「会社利益に計上」が ON だと、金額の符号を反転して会社利益に入ります（控除 −5,000 → 利益 +5,000）。OFF の調整（立替精算など）は支払額だけに影響し、会社利益には入りません。

検算の式（1 人 × 1 か月）：

```
支払額   = ドライバー売上 − ロイヤリティ − 管理費 + 調整合計
会社利益 = 単価差額利益 + ロイヤリティ + 管理費 + Σ（利益計上の調整 × −1）
会社売上 = 支払額 + 会社利益   ← 「利益計上しない調整」がある分だけ、この式はずれます
```

### 7-2. その他

| 症状 | 対処 |
|---|---|
| 「締め済みの月は変更できません」 | 4. の手順で解除してから修正（オーナー） |
| 「同じ名前が既に登録されています」 | ドライバー名・案件名・内容名は重複不可。既存を編集するか名前を変える |
| 「他のデータから参照されているため削除できません」 | 削除ではなく「停止中」にする |
| 稼働の追加候補に人・案件が出ない | 停止中になっていないか確認（設定 → ドライバー／案件・単価） |
| ドライバー本人から「明細が見えない」「集計中と出る」 | ドライバーポータルは、未締めの月を **「集計中（月締め後に確定します）」** と表示し、金額は月締め後に確定します。その月が締め済みか確認。ユーザーのロールが「ドライバー」で対応ドライバーが正しいか確認 |
| ログインできない・メールが届かない | [docs/SETUP.md](SETUP.md) 手順 13 |
| ダッシュボードに「AI 月次分析」が無い | `ANTHROPIC_API_KEY` を Vercel に設定していない場合は表示されません（任意機能）。表示されている場合は **「分析を実行」**（2 回目以降は **「再分析」**）で当月の所見を作成・保存します。**当月と前月の集計（ドライバー名を含む売上・支払・利益・管理費など）を Anthropic の API に送信**するので、外部に送りたくない場合はキーを設定しないでください |
