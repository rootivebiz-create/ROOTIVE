# 変更履歴

## 2026-09-19 運行管理と法令対応・レシートと実績ファイルの取り込み・採用と契約

軽貨物運送事業として必要な記録が 1 つも入っていなかったため、まずそこを埋めました。
マイグレーションは `0012_operations_compliance.sql` と `0013_intake_hr.sql`。

### 日報・点呼（/daily、ドライバーは「今日の報告」）

2025 年 4 月施行の制度で、黒ナンバーの事業者にも**業務前・業務後の点呼**と**業務記録**、
**点呼記録簿の 1 年保存**が義務づけられました。

- ドライバーは **1 日 1 回の「今日の報告」** で済みます：①出発前（アルコール検知・体調・日常点検・車両）→ ②今日の稼働（案件ごとの数量）→ ③終了後（アルコール検知・体調・事故の有無・走行距離）
- スタッフは日報の一覧で点呼の済み／未済を確認し、稼働報告を**承認**します
- **承認すると、その月の稼働数量に自動で合算されます**（日別 → 月次）。差戻すと外れます
- 点呼記録簿・業務記録は CSV で出せます

### 車両と書類の期限（/fleet）

- 車両（番号・所有区分・割当ドライバー・リース料・走行距離）
- **免許証・車検証・自賠責・任意保険・健康診断**の有効期限。**期限の N 日前から「気になること」に出ます**
- 期限切れがあると赤で名指し（「足立 480 あ 12-34 の車検が 3 日前に切れています」）

### 安全管理（設定 → 安全管理）

- **貨物軽自動車安全管理者**の選任・講習の記録（選任は 2027 年 3 月末まで猶予。未選任なら警告）
- **指導・監督の記録**（初任運転者への特別な指導を含む。3 年間保存）
- **事故・違反・ヒヤリハット**の記録と再発防止対策

### レシートを撮るだけで経費登録

- スマホのカメラでレシートを撮ると、**AI が金額・日付・支払先・カテゴリを読んで**下書きを作ります
- 内容を確認して「この内容で登録」を押すだけ。画像は経費に添付されて残ります

### 元請の実績ファイルの取り込み（/intake）

- 元請からもらう実績の CSV／TSV を取り込むと、**日付 × ドライバー × 案件 × 数量**に自動変換して稼働に反映します
- 列の対応と、元請側の表記（「アイソ ケイ」など）とドライバーの対応を**覚える**ので、次回からは選ぶだけ
- 対応が付かない名前はその場で選んで紐づけられます

### 採用と契約（/hr）

- **採用のパイプライン**（応募 → 連絡 → 面談 → 書類 → 契約 → 稼働開始）。必要書類のチェックリスト（運転免許証・車検証・任意保険証券・黒ナンバーの届出）
- **10 日以上動いていない応募者**を「フォロー漏れ」として名指し
- 応募者から**そのままドライバーとして登録**できます
- **業務委託契約**の期間・自動更新・通知日数。更新時期と期間切れを警告

### そのほか

- 異常の検知が 16 種類に（書類の期限切れ・期限間近・点呼の未実施・安全管理者の未選任・承認待ちの稼働報告を追加）
- **一度直ったアラートが再発したら「未対応」に戻ります**（「対象外」にしたものは戻りません）
- サイドナビを 17 項目に整理（入力／経営／管理／相談）。ドライバーポータルは「今日の報告」が先頭

### 異常の検知とアラート（/alerts「気になること」）

- 11 種類の異常を DB 側（RPC `detect_anomalies`）で洗い出します：数量 0 の稼働／マスタと違う単価／管理費のずれ／稼働が無い稼働中ドライバー／営業利益率の急落／利益がマイナスのドライバー／目標の 8 割未満／期日超過の未入金／請求書の作り忘れ／経費の未入力／30 日以内の資金ショート見込み。

- 画面を開くと 1 時間に 1 回まで自動で検査。ダッシュボードにも上位 3 件のカードを出します。CSV 出力あり。

### 社内チャット（/chat）

## 2026-09-16 税込の支払明細・消費税設定・ロゴと認印・ドライバーごとの支払日

オーナー要望「支払明細が税込になっていない（単価は全部税別で入力する）」「認印とロゴを明細に」「ドライバーによって支払日が違う」「税設定」への対応。

### 税込の支払明細

- **単価・管理費・ロイヤリティはすべて税抜で入力**し、支払明細で消費税を計算して **税込のお支払額** を出します。
  - 税抜小計 ＝ 稼働小計 − ロイヤリティ − 管理費
  - 消費税 ＝ 税抜小計 × 税率（端数処理は会社設定。既定は切り捨て）
  - お支払額（税込）＝ 税抜小計 ＋ 消費税 ＋ 調整
  - **調整（固定控除・立替など）は税込の金額として扱い、消費税を計算しません。**
- PDF・印刷用ページ・スタッフ画面・ドライバーポータル・LINE 用テキスト・個人明細 CSV のすべてで「小計（税抜）」「消費税（10%）」「お支払額（税込）」の順に表示します。
- 支払一覧と支払一覧 CSV に「消費税」「税込支払額」を追加。ダッシュボードの「ドライバー支払合計」と会社利益は従来どおり税抜です。
- 締めた月は、締めた時点の税率・端数処理・課税区分で固定されます（`driver_months.tax_*`）。締めを解除すると現在の設定に従います。

### 税設定

- **設定 → 会社設定 → 「消費税」**：消費税率（既定 10%）と消費税額の端数処理（切り捨て／四捨五入／切り上げ）。
- **設定 → ドライバー → 「消費税・支払日」**：課税区分（課税＝消費税を上乗せ／非課税・免税＝上乗せしない）と適格請求書登録番号（任意。明細に印字）。

### ロゴ・認印

- **設定 → 会社設定 → 「ロゴ・認印」** で PNG／JPEG（2MB まで）をアップロードすると、PDF と印刷用ページに印字されます（ロゴは会社名の上、認印は会社情報の横）。画像は非公開の Storage（`company-assets`）に保存し、ログイン中の自社ユーザーだけが `/api/company-asset/logo|seal` で参照できます。

### ドライバーごとの支払日

- **設定 → ドライバー → 「消費税・支払日」** で「振込予定日は会社設定に従う」を外すと、支払月（当月〜3 か月後）と支払日（末日／1〜31 日）をそのドライバーだけ変えられます。明細・ポータル・テキスト・CSV の振込予定日に反映します。

### その他

## 2026-09-16 ドライバー別単価と便利機能

オーナー要望「ドライバーごとに単価設定できるようにしてほしい」への対応と、あわせて追加した機能。

### ドライバー別単価（主機能）

- **受注単価もドライバーごとに設定できるようになりました。** これまでは支払単価だけでした（`driver_pay_overrides.bill_rate` を追加。受注・支払のどちらか一方だけの上書きも可）。
- **設定 → ドライバー別単価** 画面を新設。「ドライバーごと」（ドライバーを選んで案件内容ごとに入力）と「案件ごと」（案件内容を選んでドライバーごとに入力）の 2 つの見方。個別値には「個別」バッジ、支払 > 受注 は「赤字」。
- ドライバー編集画面の「ドライバー別単価」カードにも受注単価欄を追加。案件編集画面から「ドライバー別単価」へ移動できます。
- 稼働の自動入力（§2.5）は受注・支払ともドライバー別単価を優先します。稼働追加ダイアログには「ドライバー別」の表示。
- 単価表 CSV（全員 × 全案件内容の実効単価）。

### 単価変更を稼働に反映

- 単価・率・端数処理を変えた後、入力済みの稼働行は入力時点の値のまま（仕様）。**稼働入力**に「単価・率が現在の設定と異なる稼働行が ○ 件あります」の案内と **「マスタの値に更新」**（行ごとにチェックして一括更新）、行には「単価変更あり」バッジ。
- **設定 → ドライバー別単価** の保存後に「○年○月 の稼働に反映」。
- **ダッシュボード**の警告に「単価・率が現在の設定と異なる稼働行」を追加（締め済み月には出ません）。
- DB：`rate_diffs(month)`、`apply_master_rates(month, driver_id?, project_item_id?, entry_ids?)`（admin 以上・未締め月のみ・監査ログに記録）。
